# Stocks Index — สถิติเปิด/ปิดหุ้น

ระบบบันทึกสถิติราคา **เปิด/ปิด** ของหุ้นด้วยตัวเอง แล้วใช้สถิติที่สะสมไว้คาดการณ์ราคาปิดครั้งถัดไป

## Stack
- Next.js 16 (App Router, Server Actions) + TypeScript + Tailwind v4
- Prisma 6 + SQLite (ไฟล์ `prisma/dev.db`)
- Auth: username/password (bcrypt) + JWT ใน httpOnly cookie (`jose`)

## เริ่มใช้งาน
```bash
npm install
cp .env.example .env     # แก้ AUTH_SECRET และ SEED_USERNAME/SEED_PASSWORD ตามต้องการ
npm run setup            # generate client + สร้าง DB + สร้างผู้ใช้เริ่มต้น
npm run dev              # http://localhost:3000
```
ผู้ใช้เริ่มต้น: `admin` / `admin1234` (เปลี่ยนได้ใน `.env` ก่อนรัน `npm run setup`)

## เมนู
| หน้า | ทำอะไร |
|---|---|
| `/login` | เข้าสู่ระบบ |

## ข้อมูลที่บันทึก (ต่อวัน)
จากหน้าจอดัชนี เช่น `74,781.76  −120.83  −0.16%`
- **ตอนเปิด**: ค่าดัชนี (74,781.76) และเปลี่ยนแปลงเทียบปิดวันก่อน (−120.83)
- **ตอนปิด**: ค่าดัชนี และเปลี่ยนแปลงเทียบปิดวันก่อน
- ระบบคำนวณ % และ "ปิดวันก่อน" (= ค่าเปิด − เปลี่ยนแปลงตอนเปิด) ให้เอง
- **ตรวจตอนกรอกเปิด**: ถ้า ค่าเปิด − เปลี่ยนแปลง ไม่เท่ากับปิดล่าสุดที่บันทึกไว้ ระบบจะเตือนพร้อมค่าที่ควรเป็น (กรอกผิดหลักเดียวทำให้ D และการฟันเลขผิดทั้งวัน) — ยืนยันบันทึกตามที่กรอกได้ถ้ามีวันก่อนหน้าที่ยังไม่ได้บันทึก

## วิธีคาดการณ์ (`src/lib/stats.ts`)
แยกวิเคราะห์ตาม **เครื่องหมายตอนเปิด** — 4 รูปแบบ: เปิด+ปิด+, เปิด+ปิด−, เปิด−ปิด+, เปิด−ปิด−

เมื่อใส่ค่าเปิดวันนี้ (เช่น −120.83) จะดูประวัติ 3 กลุ่ม แล้วให้ "โอกาสปิดบวก" + ค่าปิดเฉลี่ย/มัธยฐาน ของแต่ละกลุ่ม
1. **ทุกครั้งที่เปิดเครื่องหมายเดียวกัน** (เปิด − ทั้งหมด)
2. **เปิดเครื่องหมายเดียวกัน + ขนาดใกล้เคียง** (±50% ของจุดที่เปิด)
3. **10 ครั้งล่าสุด** ที่เปิดเครื่องหมายเดียวกัน

ถ้าใส่ค่าดัชนีตอนเปิดด้วย จะได้ **ค่าปิดคาดการณ์** = ปิดวันก่อน + ค่าปิดเฉลี่ยของกลุ่ม พร้อมช่วง ±1 SD

## หุ้น VIP (`src/lib/vip.ts`)
- ดัชนีจำลองของ stocks-vip.com (ไม่ใช่ SENSEX จริง) ผล = บน 3 หลัก (หลักหน่วย + ทศนิยมราคาปิด) / ล่าง 2 หลัก (ทศนิยมของ diff)
- endpoint ไม่เป็นทางการ: `api.stocks-vip.com/api/history/{in|jp|cn|hk|tw|kr}` (ผล ~15 วัน, r1 เช้า / r2 เย็น) และ `api.stocks-vip.com/api/{market}` (ราคาวันนี้) — ไม่มี API ย้อนไกลกว่านั้น ต้องกดดึงสะสมทุกวัน
- **ผล = ฟังก์ชันของ (ราคาปิด, diff) เป๊ะทุกงวด** — ตรวจ 74 งวดที่มีราคาครบทั้ง 6 ตลาด (20–27 ก.ย. 69): `บน 3 = หลักหน่วย+ทศนิยมของราคา` และ `ล่าง 2 = ทศนิยมของ |diff|` ตรง 74/74 → ราคาปิด+diff ที่เก็บได้เป็นบันทึกที่ตรวจตัวเองได้
- **ราคาเปิดมีเฉพาะ อินเดีย/นิเคอิ/จีน/ไต้หวัน** (ฟีดมีช่อง `open`) · **ฮั่งเส็ง/เกาหลีไม่มี** — ฟีดสองตลาดนี้ให้ `prices` เป็นภาพนิ่งของราคาล่าสุด (ไม่ใช่ลิสต์รายนาที) พร้อมช่อง `results.r1/r2` = ราคา+diff ณ เวลาออกผลของรอบนั้น → เก็บ **ราคาปิดรายรอบ** ได้ทั้งเช้าและบ่าย แต่ไม่มีราคาเปิด (เดิมเอาภาพนิ่งมาเก็บเป็น `open` ได้ค่าที่ไม่ใช่ราคาเปิด — 27 ก.ย. 69 ล้าง 15 แถวของ hk/kr ที่เสียแบบนี้ทิ้ง)
- ระหว่างวัน diff = ราคา − เปิด ทุกแถว แต่แถวผลสุดท้ายไม่ตรง (18 ก.ย. 69: −92.32 vs −92.94) → ล่างของผลไม่ผูกกับบนผ่าน D จึงยังไม่ใช้โมเดลไล่กรณีกับ VIP; เก็บ open/close/diff ของวันที่ดึงทันไว้ตรวจต่อ
- **ฐานที่ diff วัดจาก (= ราคาปิด − diff) เป็นฐานเดียวกันทั้งวัน แต่ไม่เป๊ะ** — ฮั่งเส็ง 7 วันที่มีราคาครบทั้ง 2 รอบ: ฐานของรอบเช้ากับรอบบ่ายต่างกัน 0.07–1.22 จุด (ไม่ใช่ราคาปิดวันก่อน ต่างกัน 1–8 จุด) → เป็น "ราคาเปิดที่เว็บไม่ประกาศ" และทศนิยมของมันขยับระหว่างรอบ **จึงเอาล่างของรอบเช้าไปคำนวณล่างของรอบบ่ายไม่ได้**
- **ล่าง 2 ตัวไม่ผูกกับบน** (ทดสอบฮั่งเส็ง 1,353 วัน): `ล่าง − ทศนิยมบน` เท่ากันทั้งสองรอบ 1.6% · `ล่างบ่าย = ±(บน2บ่าย − บน2เช้า)` 1.9% · ข้ามวัน 1.5% — ทั้งหมดเท่าเส้นสุ่ม → ราคาช่วยได้แค่ "อ่านผลเร็วขึ้น/ตรวจผล" ไม่ช่วยทำนายล่าง

### สูตรต่อตลาด (`src/lib/formulas/`)
- สูตรของใครของมัน 1 ตลาด = 1 ไฟล์ ไม่ import กัน; `formulas/index.ts` เป็นทะเบียน (ตลาดที่ยังไม่มีไฟล์ใช้ `formulas/vip.ts` = เลขร้อน + ทดลองจากตัวเปิด)
- **เลขที่ "ออก" ของ VIP** = เลขโดดใน 2 ตัวบน (2 หลักท้ายของบน 3) + 2 ตัวล่าง — หลักร้อยไม่นับ → สุ่ม 34% ต่อเลข, 2 ตัว ≥1 59%
- `formulas/cn.ts` **หุ้นจีน VIP** — **ฝึกโมเดลใหม่ 27 ก.ย. 69 ด้วย 2,726 งวด** (เดิมฝึกถึง 23 ก.ย. และ `cn.json` หยุดที่ 18 ก.ย. → อัปเดตจากฐานข้อมูลแล้ว เพิ่ม 17 งวด ไม่มีงวดขัดแย้ง) · วัดแบบฝึกโมเดลใหม่ทุก fold 1,500 งวดที่ไม่เคยเห็น **และวัดผ่านท่อสูตรจริง**: ★ 36.2% / 2 ตัว 62.8% (สุ่ม 33.1 / 57.3) เทียบกับเอา 2 อันดับแรกดิบ ★ 35.9% / 2 ตัว 60.1% → **กฎรอบบ่าย (ตัดเลขรอบเช้า + widestPair) เพิ่มช่อง 2 ตัวจริง +2.7 จุด** · ขั้นตอนฝึกตรงกับ ml4.py เดิม (cosine 0.980)
- `formulas/cn.ts` (ต่อ) **แยกรอบ: เช้า ★ 39.1% / 2 ตัว 62.4% · บ่าย ★ 33.3% (เท่าสุ่ม) / 2 ตัว 63.2%** → รอบบ่ายอย่ายึดตัว ★ ให้เล่นทั้งคู่ เพราะ widestPair ตั้งใจแลกความแม่นของตัวแรกไปเพิ่มโอกาสของคู่ (ขึ้นบนการ์ดแล้ว) · 500 งวดล่าสุดยังอยู่ทรง ★ 35.2% / 2 ตัว 63.4% (ต่างจากฮั่งเส็งที่ขอบบางลง) · ยังไม่แสดงป้าย "งวดแข็ง" เพราะยังไม่นิ่ง (≥40% แต่ละช่วงได้ 27/40/39/31/37/43%) · ประวัติเดิมจาก raakaadee.com ตรงกับ API ของเว็บ; ล่างไม่เคยซ้ำล่างงวดก่อน (0/2,709) ตัดจากเลขเจาะ

## วิเคราะห์เลขปิด (`src/lib/digits.ts`)
- **2 ตัวบน** = หลักหน่วย + ทศนิยมตำแหน่งแรกของค่าดัชนีตอนปิด (74,781.76 → `76`, ไม่นับหลักร้อย)
- **2 ตัวล่าง** = ทศนิยม 2 ตำแหน่งของค่าเปลี่ยนแปลงตอนปิด (−120.83 → `83`)
- ใส่เลขเปิดวันนี้ → ให้ % ที่เลข 0–9 แต่ละตัวจะโผล่ตอนปิด จากหลักฐาน: อยู่ในเลขเปิด / อยู่ในปิดเมื่อวาน (เด้ง) / เด้งติดกัน ≥2 วัน / ความถี่ช่วงหลัง (ถ่วงน้ำหนัก + smoothing เมื่อข้อมูลน้อย)
- **ฟันเลขเดี่ยว** = D (ทศนิยมปิดวันก่อน) + ทิศทาง → ไล่ทุกกรณี บน 00–99 ว่าเลขไหนโผล่ใน บน∪ล่าง บ่อยสุด (เพดานทางคณิตศาสตร์ ≈ 36% เพราะทศนิยมปิดสุ่มจริง) แสดง % ของทุกเลข 0–9 (calibrated กับ 10 ปี)
- **ฟัน 2 ตัว** = ตัวหลัก (โอกาสโผล่สูงสุด) + ตัวรอง (ตัวที่ทำให้ "อย่างน้อย 1 ใน 2 โผล่" สูงสุด) → 10 ปี: ตัวหลัก 36%, ≥1 ใน 2 = 63.5% (สุ่ม 59%) — แต่ละตัวบอก % ต่อตำแหน่ง (บน/ล่าง × หลักสิบ/หลักหน่วย) และ "ถ้ามา → อยู่หลักสิบ/หน่วยกี่ %" ซึ่งปกติ ~10% ต่อตำแหน่ง จะเอียงเฉพาะวันที่ D ลงท้าย 0 หรือ 9 (ราว 1 ใน 5 วัน; วันแบบนั้นเลขที่มาอยู่ฝั่งที่เอียง 60%)
- **★ ตัวเด่น** = 1 ใน 2 ตัวที่ฟัน: โอกาสวันนี้สูงกว่า ถ้าเสมอ → เลขที่โผล่บ่อยกว่าในประวัติ (ฐาน SENSEX 10 ปี `DIGIT_BASE_RATE` น้ำหนัก 300 วัน + ข้อมูลของหุ้นนี้) — เป็นแค่กฎเลือกตัวที่จะเน้น คาดหวัง ~36% เท่าเลขเดี่ยวทั่วไป
- ตัวสำรอง (`pickTwo().third/.fourth`) ยังคำนวณอยู่ในโมเดล (3 ตัว ≥1 = 82%, 4 ตัว 94% บน 10 ปี) แต่ไม่แสดงบนหน้าจอ
- **เลขเจาะ** (`pickTwo().drill`) = จากเลขที่ฟัน 2 ตัว ให้เลข 2 ตัวชุดละ 6 ตัว (`DRILL_PER_DIGIT`, เช่น 9 → 98 90 91 92 93 95) นับว่ามาเมื่อเท่ากับ บน หรือ ล่าง ตรงหรือกลับ (โต๊ด) — ไล่ 200 กรณีเหมือนเลขเดี่ยว แต่เมื่อ บน สุ่ม ทุกเลข 2 ตัวมีโอกาส ~4% เท่ากัน สิ่งเดียวที่เลือกได้คือ "อย่าให้เลขในชุดมาในกรณีเดียวกัน" (บางคู่ผูกกันผ่าน D) → เลือกทีละตัว (greedy) ให้ "≥1 ใน 12 ตัวมา" สูงสุด ชุดละ 6 เท่ากัน: 10 ปี ทั้งวัน 47.5% (เลือกแยกชุด 45.5%, สุ่ม 40%, เพดาน 48%) ต่อชุด 24.2% — เป็นเส้นตรงตามจำนวน (3 ตัว 12.6% · 4 ตัว 16.5% · 5 ตัว 20.7% ต่อชุด ≈ 4.1% ต่อเลขทุกขนาด ลดจำนวนแล้วไม่แม่นขึ้น); ลองกฎเลือกคู่ 12 แบบ (เลขร้อน/เย็น, เลขเปิด, โอกาสเลขเดี่ยว, คงที่) ได้เท่ากันหมดในระดับ noise
- **คู่ผูก** = เลือก 2 เลขที่ "มาทั้งคู่" บ่อยสุดจากการไล่ 200 กรณี (ล่าง = บน ∓ D ทำให้บางคู่ผูกกัน) → มาทั้งคู่ ≈ 18% บน 10 ปี เทียบ 10% ถ้าสุ่ม; ระดับ "คู่แข็ง" ≥ 22%
- เลขที่เสมอกัน (ต่างกันแค่ floating point) เรียงเลขน้อยก่อนเสมอ เพื่อให้ทุกหน้าฟันเลขเดียวกัน
- **Backtest** แบบ walk-forward: ทายทุกวันที่ผ่านมาด้วยข้อมูลก่อนหน้าวันนั้น แล้วรายงาน % ที่ 1/2/3 เลขอันดับแรกโผล่จริง เทียบกับสุ่มเดา
